# ADR-005 — Variant scope and engine strategy (no studied engine plays Brazilian)

- Status: **Accepted: option A** (owner decision at G1 review, 2026-11-20)

## Context

The project vision assumes that SCAN and KingsRow can be integrated for Brazilian 8x8. G1
established that this is false for every published build:

- Scan 3.1 is 10x10 only, at compile time (`File_Size {10}`). Lidraughts confirms it "only knows
  100-square variants".
- Kingsrow has English 8x8, Italian 8x8 and International 10x10 builds. There is no Brazilian
  build.

Brazilian draughts has the rule logic of International draughts on an 8x8 board, so the gap is
geometry plus trained data (Scan), or rules (Kingsrow 8x8).

## Options

| Option | Description | Pros | Cons / cost |
|---|---|---|---|
| **A. Brazilian-first, engine-agnostic** (recommended) | Build the Rules Core for Brazilian 8x8 (G2) and the adapter framework (G3) as planned. Re-scope G4/G5: integrate SCAN and Kingsrow International **on 10x10 International** as a validation testbed for the framework, consensus and benchmarking. In parallel, search for Brazilian-capable engines (candidates to investigate: the Aurora Draughts program found on this machine, others named in community forums; none verified) | Keeps the product goal. Reuses SCAN/KR where they are valid. All framework gates still get real engines | The Rules Core needs a 10x10 geometry too (cheap: same rules, parameterized). Brazilian multi-engine consensus depends on finding Brazilian engines or on the internal engine (G8+) |
| B. Port Scan to Brazilian 8x8 | Fork Scan (GPL-3.0) and change geometry, move generation tables, eval training, bitbase generation, book | Gives a strong Brazilian engine with a known protocol | Large research effort (eval retraining, bitbases). GPL derivative in a separate repo. Strength is unknown until done. This is effectively G14-level work moved early |
| C. Switch the target to International 10x10 | Make the platform an International draughts platform | SCAN and Kingsrow International both work over Hub now | Abandons the stated Brazilian goal |
| D. Use Kingsrow English/Italian for Brazilian | | | **Rejected**: wrong rules (INC-2). Output would be invalid by construction |

## Recommendation

Choose **A**, and keep B as a candidate research track for G8/G14. Concretely:

- G2: Rules Core with geometry parameterization. Brazilian 8x8 is the primary deliverable,
  and a 10x10 International geometry is added only to the extent needed to validate engine
  moves in G4/G5.
- G4/G5 acceptance criteria change from "analyse Brazilian positions" to "integrated,
  conformance-tested on the variant the engine actually plays".
- Open a discovery item: "identify and evaluate Brazilian-capable engines". It needs owner
  approval for each download or contact.

## Decision

**Option A is adopted** (owner, 2026-11-20). Brazilian-first, engine-agnostic:

1. **Target variant:** Brazilian 8x8 remains the product's primary variant.
2. **Rules Core (G2):** geometry-parameterized. Brazilian 8x8 is the full deliverable.
   International 10x10 geometry is included only as far as needed to validate SCAN and
   Kingsrow International moves under ADR-001. It shares the same rule logic.
3. **G4 (SCAN)** integrates Scan 3.1 via Hub v2 on **International 10x10**. Acceptance:
   integrated and conformance-tested on the variant Scan actually plays.
4. **G5 (KingsRow)** integrates **Kingsrow hub 1.63 (International 10x10)** under the same
   acceptance criterion. Kingsrow English/Italian (CheckerBoard DLL) are **out of scope**, and so
   is the CB host process. They may be reconsidered by a later ADR.
5. **Brazilian engine discovery** is an open, standing work item. Each candidate is investigated
   only with owner approval for downloads or contact. Aurora Draughts (installed demo) is the
   first candidate.
6. **Option B (Scan 8x8 port)** stays a candidate research track for G8/G14. It is not
   scheduled.
7. Options C and D are rejected.

## Consequences

- Multi-engine analysis and consensus (G6/G7) are developed and validated on International
  10x10 first. They apply to Brazilian once at least two Brazilian-valid evidence sources exist:
  the internal engine (G8) plus any engine found by item 5.
- Every engine and every stored analysis carries an explicit variant tag. Capability gating
  (ADR-002 §6) is mandatory, not optional.
- The 10x10 rule claims tagged [K] in `rules-compatibility.md` (International column) must be
  verified against the FMJD rules before G4 conformance tests rely on them.
