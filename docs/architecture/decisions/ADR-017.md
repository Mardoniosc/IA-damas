# ADR-017 — Interface: Angular workbench over the local API, honest about evidence

- Status: **Accepted** (G15, 2026-11-20). Build and browser verification pending the npm
  dependency install approval.

## Context

The stack names Angular + TypeScript for the frontend. The platform's value is evidence plus
judgement (G6–G14), so the interface must show not only *what* the platform recommends but *how
sure* it is and *why*. Angular CLI 21.0.2 is installed globally. The project's npm dependencies
are not in the local cache, so installing them is a download that needs the owner's approval.

## Decision

1. **One-page analysis workbench** (`frontend/damas-ui`): variant selector, FEN input, time per
   move, internal-engine depth, and "Analyse". It shows:
   - a board (SVG) rendered from the FEN, with the recommended move highlighted;
   - the **decision** (G10): move, **confidence badge**, reasons, and the candidate table with
     per-engine normalized regret and vetoes;
   - **tactics / criticality** (G9) with the forcing line;
   - the **strategic profile** (G10, labelled descriptive);
   - engine status, and knowledge-base counts (G11).
2. **Explicit evidence warnings**: when a variant has no engine, or only one (Brazilian today),
   the page says so and states that confidence is capped.
3. **API only.** The UI calls the FastAPI backend through the dev-server proxy (`/api` →
   `127.0.0.1:8765`, so no CORS and the API stays local). It never talks to engines and never
   decides legality (ADR-001).
4. **Board numbering is shared with the backend** and pinned by unit tests (`board.ts`,
   `app.spec.ts`).
5. Standalone components and signals (Angular 21 defaults), with no extra UI libraries.

## Consequences

- Until `npm install` is approved, the UI source is unbuilt and unverified. The backend
  endpoints it calls were verified end to end over HTTP in G15.
- Authentication is still absent (R19). The UI is for local use only.
