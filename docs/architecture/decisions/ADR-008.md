# ADR-008 — Multi-engine orchestration: pool, thread budget, run modes, first HTTP API

- Status: **Accepted** (G6, 2026-11-20)

## Context

G6 runs one position through several engines. ADR-007 fixed one search per engine process.
G6 needs engine lifecycle across many requests, CPU governance, a way to compare engines
fairly, and a first external interface. G6 evidence (300 positions, Scan + Kingsrow, 0.2 s per
move, 16-core machine, 1 thread each) showed that **running engines in parallel reduces each
engine's search effort**: median nodes fell 22% (Scan) and 33% (Kingsrow), and depth fell
0.5–0.8, compared with sequential runs.

## Decision

1. **EnginePool** owns one adapter per enabled engine: lazy start, `warm_up()`, status, and
   automatic replacement of a dead process on next use (counted as a restart).
2. **Thread budget**: the sum of engines' `threads` params running at once must stay within
   `DAMAS_ENGINE_THREAD_BUDGET` (default: CPU count). Exceeding it raises
   `ThreadBudgetExceeded`.
3. **Two run modes**: `parallel` (throughput; default for interactive analysis) and
   `sequential` (equal conditions per engine; **required for benchmarks and any comparison of
   engine effort**, G12).
4. **Results are descriptive in G6**: per-engine `AnalysisResult` plus `proposals` (best moves
   grouped by identity, with the engines behind each). Agreement metrics, divergence and score
   calibration are G7.
5. **Capability first**: engines are selected by variant. If none plays it (Brazilian today),
   the result says so explicitly instead of returning nothing silently.
6. **Reproducibility**: every result carries a run id, timestamps, mode, ruleset id, the limit,
   engine names and versions, and a fingerprint of the engine configs used. The batch CLI
   writes one self-contained JSON record per position (`schema_version: 1`).
7. **First HTTP API** (FastAPI, served by uvicorn): `GET /health`, `GET /variants`,
   `GET /engines`, `POST /analyses`. It is local-first with **no authentication, so bind to
   127.0.0.1**. Endpoints are synchronous and run in FastAPI's thread pool.

## Consequences

- FastAPI and uvicorn become runtime dependencies; httpx is a dev dependency (TestClient).
- An authentication/authorization decision is required before any non-local deployment.
- Persistence of results is still files (JSONL). The database arrives with G11 or when needed.
