# ADR-013 — Knowledge base: SQLAlchemy + Alembic, SQLite verified, PostgreSQL-ready

- Status: **Accepted** (G11, 2026-11-20)

## Context

The stack names PostgreSQL + SQLAlchemy + Alembic. On the development machine, SQLAlchemy 2.0.44
and Alembic 1.17.1 are installed, but **there is no PostgreSQL server and no PostgreSQL driver**.
Installing either is a download of new third-party software, which is outside the owner's
standing authorization (gates and commits). The earlier gates already emit self-contained JSON
records (G6–G10).

## Decision

1. **SQLAlchemy 2.0 ORM with portable types** (Integer, BigInteger, String, Float, Boolean,
   JSON, timezone-aware DateTime), so the same models run on SQLite and PostgreSQL.
2. **Alembic owns the schema.** Migration `0001` is hand-written. A test proves it matches the
   ORM exactly (autogenerate diff is empty), and the downgrade is tested.
3. **Default backend: SQLite file** (`DAMAS_DATABASE_URL`, e.g. `sqlite:///var/damas_kb.sqlite3`).
   It is local-first with zero infrastructure. In-memory SQLite uses a shared `StaticPool`.
   **PostgreSQL is supported by configuration but NOT verified** until a server and driver
   (e.g. `psycopg`) are approved and installed.
4. **Schema**: `positions` (unique per variant + DSA; `canonical_dsa` groups colour-flipped
   twins; signed-64-bit Zobrist), `engine_analyses`, `consensus_records` (consensus and
   adaptive, with trajectory), `tactical_records`, `decisions`, `tags`. Each record keeps its
   provenance and the producing gate's JSON (`detail`).
5. **Ingestion from the gates' JSONL** (`python -m damas_ai.kb ingest --kind …`), so evidence
   produced by any CLI or API call can be loaded later. Automatic tags: `critical`, `tactics:*`,
   `divergence:*`, `proof_gap`, `stable_divergence` (diverged at every adaptive level).
6. **Read API**: `GET /kb/stats`, `/kb/positions` (filters: variant, tag, classification,
   critical), `/kb/positions/{id}`.

## Consequences

- PostgreSQL verification is an open item (risk R22) that needs owner approval for the
  server/driver install.
- JSON columns keep the full gate output. Heavy analytics may later need normalized columns
  (add them by migration).
