# ADR-002 — Out-of-process engine adapters behind an engine-agnostic interface

- Status: **Accepted** (G1, 2026-11-20)

## Context

Verified interfaces (engine-integration.md §1):

- Scan 3.1 is a console program speaking Hub v2 over stdin/stdout.
- Kingsrow International ships a "hub" build (Hub dialect unverified).
- Kingsrow English/Italian are **Windows DLLs loaded in-process** through the CheckerBoard API
  (`getmove`, `enginecommand`). The 64-bit build 1.21 is current. The 32-bit build 1.19e is frozen.
- Score semantics differ between engines (INC-6).

Running a third-party DLL inside the platform process would let an engine crash or leak the
platform, and would violate the principle of independent engine processes.

## Decision

1. Analysis code depends only on an `EngineAdapter` interface (capabilities, start, analyze,
   stop) and platform types. **No engine-specific type crosses the adapter boundary.**
2. **Every engine instance runs in its own OS process**, supervised by a `ProcessSupervisor`
   (line I/O, deadlines, quit → terminate → kill escalation, full transcript).
3. DLL engines run inside a dedicated **engine host process**. This is a small program that
   loads the DLL and exposes a line protocol (JSON lines) on stdin/stdout. Its bitness must
   match the DLL's (64-bit for Kingsrow 1.21).
4. One protocol adapter per protocol (Hub, CB-DLL-host). Engine-specific quirks are handled in
   thin engine profiles (`engines.scan`, `engines.kingsrow`) on top of them.
5. Adapters return `raw_score` and its declared unit. Cross-engine normalization is a
   separate, versioned, empirically calibrated component (G7/G12). Scores are never compared
   raw.
6. Capability gating: an engine receives only positions of variants it declares (and has passed
   conformance for).

## Consequences

- The process boundary costs little (text pipes), and it gives isolation, kill-ability and
  GPL arm's-length separation for Scan (see ADR-004).
- The CB host is extra code. Under ADR-005 option A the Kingsrow 8x8 DLL builds are out of
  scope, so the host is **not built**. Point 3 stays as the rule for any future DLL engine.
- The G1 PoC (`scripts/poc/hub_poc.py`) already exercises steps 2 and 3 of this design against
  a test double.
