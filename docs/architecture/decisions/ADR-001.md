# ADR-001 — The internal Rules Core is the sole legal-move authority

- Status: **Accepted** (G1, 2026-11-20)
- Deciders: architecture (G1). To be ratified by the project owner at G1 review.

## Context

The platform will consult several external engines. G1 found that:

- no studied engine implements Brazilian rules (rules-compatibility.md INC-1/2/3);
- Hub move notation omits capture pivots and order, so it can be ambiguous (INC-4);
- engines can crash, hang, or emit malformed output, and they run different rule sets.

If any engine were trusted as the arbiter of legality, a rules mismatch would silently corrupt
analyses, the knowledge base and any training data.

## Decision

1. `damas_ai.rules` (G2) is the **only** component that decides which moves are legal, applies
   moves, and decides game termination and draws.
2. Every move produced by an engine (best move, ponder move, each PV move) is resolved against
   the Rules Core's legal-move list for that position. A move that cannot be matched is an
   `EngineProtocolViolation`. It is recorded as data and never applied.
3. Engines are **advisors**: their output is evidence with provenance (engine id, version,
   limits, transcript).
4. The Rules Core is versioned by `ruleset_id`. Any stored analysis references the ruleset it
   was validated against.

## Consequences

- G2 must deliver a correct and well-tested move generator before any engine adapter is useful.
- A move-validation cost is paid on every engine reply. It is negligible compared with search
  time.
- Engines whose rules differ from Brazilian can be detected empirically, through the share of
  violations on a conformance suite.
